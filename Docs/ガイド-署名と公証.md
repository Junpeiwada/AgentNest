AgentNest を Apple Developer ID で **コード署名** し、Apple の **公証（notarization）** を通すための
仕組みとセットアップ手順をまとめる。

---

## なぜ必要か

AgentNest はプロジェクト群（既定で `~/Documents/Project`）配下のファイルを読み書きする。
macOS の TCC は `~/Documents` / `~/Desktop` / `~/Downloads` へのアクセスを必ず許可確認する。

許可ダイアログは本来「一度許可すれば次回から出ない」が、**アプリのコード署名が不安定だと
許可が永続化されず毎回出る**。アドホック署名（`Signature=adhoc` / `Sealed Resources=none`）の
ビルドはコード識別子が安定せず、TCC が「許可」を保存できないためダイアログが無限に出る。

これを解決するのが **安定した Developer ID 署名**。さらに他の Mac へ配布する場合は
Gatekeeper を通すために **公証 + staple** が必要になる。

| 目的 | 必要な対策 |
|------|-----------|
| 自分の Mac で TCC 許可を永続化（ダイアログを止める） | Developer ID **署名** のみで足りる |
| 他の Mac / 配布で Gatekeeper 警告を出さない | 署名 **＋ 公証（notarization）＋ staple** |

## 全体の仕組み

1. **外周署名**: `src-tauri/tauri.conf.json` の `bundle.macOS.signingIdentity` に
   Developer ID を指定。`tauri build` 時に `.app` 本体が Developer ID + hardened runtime で署名される。
   → これだけでローカルインストール版の TCC ループは解消する。
2. **入れ子バイナリ署名**: バンドル内 `dist-server/` には sharp / ripgrep / audio-capture などの
   ネイティブモジュール（`.node` = darwin Mach-O）が含まれる。Apple の公証は
   **バンドル内の全 Mach-O** が署名済みであることを要求するため、
   [scripts/build-server.mjs](../scripts/build-server.mjs) が Tauri のバンドル前に
   これらを「内→外」順で署名する（`APPLE_SIGNING_IDENTITY` が設定されているときのみ）。
3. **公証 + staple**: `APPLE_API_*` 環境変数が揃っていると、`tauri build` が App Store Connect
   API キーで notarytool に提出し、結果を `.app` に staple する。DMG / updater 用 `.app.tar.gz` は
   staple 済みの `.app` から作られる。
4. **検証ゲート**: [scripts/release.sh](../scripts/release.sh) がビルド後に
   `codesign --verify` と `stapler validate` を実行し、不正な成果物のアップロードを止める。

ポイント: 署名 ID の真実の源は **`tauri.conf.json` の 1 箇所**。`release.sh` はそこから
`APPLE_SIGNING_IDENTITY` を読み出して `build-server.mjs` の入れ子署名に渡す。

## 一度きりのセットアップ

### 1. Developer ID 証明書（署名用）

`security find-identity -v -p codesigning` で
`Developer ID Application: Junpei Wada (L897K2C26B)` が表示されれば導入済み。
無い場合は Dropbox の `証明書.p12` を Keychain にインポートする（パスワードは原本フォルダの
`名称未設定.txt` を参照。**このリポジトリは公開なので doc には書かない**）:

```bash
security import "/Users/junpeiwada/Dropbox/アプリ/GainForge/証明書.p12" \
  -P '<.p12のパスワード>' -T /usr/bin/codesign
```

### 2. App Store Connect API キー（公証用）

公証は **App Store Connect API キー方式** を使う（app 固有パスワードより堅牢）。
必要な 3 点:

AgentNest 専用の API キーを使う（原本は `/Users/junpeiwada/Dropbox/アプリ/AgentNest/`）。
**このリポジトリは公開のため、具体的な Key ID / Issuer ID / .p8 は doc に書かず**、
git 管理外の `~/.tauri/AgentNest.notary.env`（実値は記入済み）と Dropbox 原本にのみ置く。

| 値 | 内容 | 取得元 |
|----|------|--------|
| Key ID | `.p8` ファイル名 `AuthKey_XXXX.p8` の XXXX 部分 | Dropbox の `キーID.txt` |
| `.p8` パス | API 秘密鍵ファイル | Dropbox の `AuthKey_XXXX.p8` |
| Issuer ID | App Store Connect → ユーザーとアクセス → 統合 → App Store Connect API の「Issuer ID」（UUID） | App Store Connect 画面、または `~/.tauri/AgentNest.notary.env` |

### 3. 認証情報ファイル `~/.tauri/AgentNest.notary.env`

`release.sh` がこのファイルを `source` する。実値は記入済み。フォーマットは以下（値はプレースホルダ）:

```bash
export APPLE_API_KEY=<Key ID>
export APPLE_API_ISSUER=<Issuer ID の UUID>
export APPLE_API_KEY_PATH="/Users/junpeiwada/Dropbox/アプリ/AgentNest/AuthKey_<Key ID>.p8"
```

このファイルは `~/.tauri` 配下で git 管理外。`.p8` と Issuer ID は秘密情報なので共有しない。

## リリース時の流れ（自動）

`npm run リリース`（[scripts/release.sh](../scripts/release.sh)）が以下を自動実行する:

1. `tauri.conf.json` から署名 ID を読み出し `APPLE_SIGNING_IDENTITY` に展開
2. `~/.tauri/AgentNest.notary.env` を読み込み、公証情報が揃えば `NOTARIZE=1`
   （揃わなければ警告して公証なしで続行）
3. `tauri build` →
   - `build-server.mjs` が入れ子 `.node` を署名
   - Tauri が `.app` を署名 → 公証提出 → staple → DMG / updater 生成
4. `codesign --verify` と（公証時）`stapler validate` で検証。失敗したら中断
5. GitHub Releases へアップロード・公開

## 検証コマンド（手動確認用）

```bash
APP=/Applications/AgentNest.app   # またはビルド成果物の .app

# 署名の確認（adhoc でなく Developer ID / TeamIdentifier=L897K2C26B になっていること）
codesign -dvvv "$APP"

# 公証チケットが staple されているか
xcrun stapler validate "$APP"

# Gatekeeper 評価（accepted: notarized developer id になること）
spctl -a -vvv --type execute "$APP"
```

## トラブルシューティング

- **公証がスキップされる / `stapler validate` で失敗**
  `~/.tauri/AgentNest.notary.env` の `APPLE_API_ISSUER` が未設定（`REPLACE_WITH_ISSUER_UUID` のまま）。
  Issuer ID を正しい UUID に置き換える。
- **公証で「The binary is not signed with a valid Developer ID certificate」**
  バンドル内の入れ子 Mach-O が未署名。`build-server.mjs` の署名工程が動いていない
  （= `APPLE_SIGNING_IDENTITY` が未設定でビルドされた）。`release.sh` 経由でビルドすること。
- **`security find-identity` に Developer ID が出ない**
  証明書未インポート。上記「Developer ID 証明書」の手順で `.p12` を入れる。
- **既にインストール済みの旧（adhoc）版で許可が止まらない**
  新しい署名版を再インストール後、システム設定 → プライバシーとセキュリティ →
  フルディスクアクセス / 書類フォルダ の項目から旧エントリを削除し、署名版で再許可する。

- API キー（AgentNest 専用）の原本: `/Users/junpeiwada/Dropbox/アプリ/AgentNest/`
  （`AuthKey_XXXX.p8` / `キーID.txt`）
- 証明書（Developer ID、GainForge と共用）の原本: `/Users/junpeiwada/Dropbox/アプリ/GainForge/`
  （`証明書.p12` / `.cer`、`.p12` パスワードは同フォルダの `名称未設定.txt` を参照）
- updater 署名キー（別物・minisign）: `~/.tauri/AgentNest.key`
