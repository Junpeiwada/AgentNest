## 概要

タブを閉じるとサーバ上で動き続けているAgentに二度と辿り着けない。`connectionId` が「混線防止の単位」と「実行中Agentの宛先」を兼務し、`sessionStorage` でタブと寿命を共にしているため。この1本のIDを `agentId`（サーバ発行・実行1本ごと）と `clientId`（ブラウザ単位・所有者）に分離し、実行中Agentを一覧から選んで復帰できるようにする。

- **対象**: サーバのセッションキーを `agentId` に変更、`clientId` による所有者管理、実行中Agent一覧API、フロントの再接続UI
- **やらないこと**: 認証・ログイン（`clientId` は所有者の識別であって認証ではない。推測されれば他人のAgentを覗ける前提は現状と同じ）／セッション状態のディスク永続化（サーバ再起動で実行中状態は失われる。会話履歴はClaude CLIのJSONLに残る）／リポジトリ単位のアクセス制御
- **関連**: [アーカイブ/実装方針-マルチセッション対応.md](アーカイブ/実装方針-マルチセッション対応.md)（前身。`connectionId` 導入の経緯と混線の原因はこちら）、[仕様-AgentNest全体.md](仕様-AgentNest全体.md)、[ガイド-テスト.md](ガイド-テスト.md)

### 設計の決定事項

| 論点 | 決定 |
| --- | --- |
| `Map` のキー | `agentId`（サーバ発行UUID、実行1本ごと）。`connectionId` は廃止 |
| 所有者 | `clientId`（クライアント発行UUID、`localStorage`、ブラウザ単位で不変） |
| 伝達方法 | ヘッダ `X-Client-Id` と `X-Agent-Id`。既存の `X-Connection-Id` は受理しない |
| 同一ブラウザの同時Agent数 | 複数可。1タブから複数リポジトリを並行実行できる |
| 「後勝ちabort」 | 廃止。送信時は明示された `agentId` を継続するか、新規Agentを起こす |
| 他人のAgentへの操作 | `clientId` 不一致は404（存在を秘匿する） |
| Agent一覧の範囲 | 自分の `clientId` のもののみ |

## フェーズ1: サーバのキーを agentId 化

**目標**: サーバ内部が `Map<agentId, Session>` になり、API契約は従来のまま単一タブで動作する。

`Map` のキーを差し替え、`clientId` を Session のフィールドとして持たせる。このフェーズでは API 契約を変えず、ルート側は受け取った `X-Connection-Id` を暫定的に `clientId` として扱い、`agentId` はその `clientId` の最新Agentを引くことで従来動作を保つ。単体で起動・動作を確認できる単位に収めるのが狙い。

### タスク

- [x] **P1-1**: `sanitizeConnectionId` を `sanitizeId` に一般化し、`clientId` / `agentId` 両方の検証に使えるようにする（`server/routes/connectionId.ts`）
- [x] **P1-2**: `Session` 型の `connectionId` を `agentId` + `clientId` の2フィールドに置換し、`createdAt` を追加（`server/claude/executor.ts`）
- [x] **P1-3**: `sessions` の型を `Map<string, Session>`（キー= `agentId`）に変更し、`clientId` から引くための索引関数 `findAgentsByClient(clientId)` を追加（`server/claude/executor.ts`）
- [x] **P1-4**: `getSession` / `subscribeToSession` / `abortSession` / `interruptSession` / `resolvePermission` / `resolveQuestion` を `agentId` 引数に変更し、`clientId` 照合を行う版のラッパーを用意（`server/claude/executor.ts`）
- [x] **P1-5**: `executeChat` が `agentId` を新規発行して返すようにし、冒頭の無条件 `abortSession` を「明示的に継続指定されたAgentのみ中断」に変更（`server/claude/executor.ts`）

## フェーズ2: API契約の切り替え

**目標**: `X-Client-Id` と `X-Agent-Id` で任意のAgentを名指しでき、`curl` で「タブを閉じた後の復帰」に相当する操作ができる。

- [x] **P2-2**: `POST /api/chat` が `X-Client-Id` を必須で受け取り、body の `agentId`（省略時は新規）で継続先を決め、SSE 冒頭に `agent_id` イベントを流す（`server/routes/chat.ts`）
- [x] **P2-3**: `GET /api/reconnect` を `X-Client-Id` + `X-Agent-Id` 対応にし、所有者不一致は404にする（`server/routes/reconnect.ts`）
- [x] **P2-4**: `POST /api/permission` を `X-Client-Id` + `X-Agent-Id` 対応にし、他 `clientId` の `requestId` は404で弾く（`server/routes/permission.ts`）
- [x] **P2-5**: `POST /api/interrupt` と `GET /api/status` を `X-Client-Id` + `X-Agent-Id` 対応にする（`server/routes/status.ts`、`/api/status` のヘッダ無しヘルスチェック互換は維持）

### 完了確認

```bash

  -H 'X-Client-Id: 11111111-1111-1111-1111-111111111111' \
```

## 注意点

- **前身の混線の原因はサーバのグローバル変数**で、それは `Map` 化で解決済み。今回キーを差し替えるにあたり、`executeChat` 冒頭の abort を「他Agentを絶対に止めない」性質ごと壊さないこと（[executor.ts](../server/claude/executor.ts) の該当箇所にその旨のコメントがある）
- **`clientId` は認証ではない**。`localStorage` の値を知られれば他人のAgentを操作できる。現状の「認証なし・LAN/Tailscale前提」の運用と同じ前提に立つが、`connectionId` 時代よりIDの寿命が長くなる分、漏洩の影響は持続する
- **後勝ちabortの廃止はUXの変更**。これまで「送信すれば前の実行が止まる」前提だった操作が、明示的な停止または新規Agent起動に変わる。停止ボタンの導線を確認すること
- **`/api/status` のヘッダ無しヘルスチェック**は Tauri の起動待ち（`src-tauri/src/server.rs` の `wait_for_server`）が使っている。400にするとアプリが起動不能になるため、互換を維持する
- **SDK子プロセスがAgent数だけ起動する**。1タブから何本でも起こせるようになるため、フェーズ5の上限が前身より重要になる
- **`server/routes/{files,git,repos,sessions,models}.ts` は対象外**。リクエストごとに完結し共有状態を持たない
