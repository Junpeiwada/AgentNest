## 概要

サーバのセッション状態が単一のグローバル変数だったため、複数端末・複数タブから同時に使うと実行が中断され、他人（他タブ）の出力が自分の画面に流れ込んでいた。これを `connectionId` をキーにしたセッション分離に作り替える。

- **対象**: サーバのセッション管理をMap化し、チャット系APIすべてに `connectionId` を通す。フロントはタブ単位で `connectionId` を発行する
- **やらないこと**: 認証・ログイン画面・ユーザー管理／リポジトリ単位のアクセス制御／セッション状態のディスク永続化（サーバ再起動で実行中状態は失われる。会話履歴はClaude CLIのJSONLに残る）
- **関連**: [仕様-AgentNest全体.md](仕様-AgentNest全体.md)（「シングルセッション制」の記述を本計画で更新する）、[ガイド-テスト.md](ガイド-テスト.md)

### 設計の決定事項

| 論点 | 決定 |
| --- | --- |
| 識別子 | クライアント発行のUUID `connectionId`。タブ単位（`sessionStorage`）で1つ |
| 伝達方法 | HTTPヘッダ `X-Connection-Id`。全チャット系APIで統一（URLが変わらないため既存テストのモックを壊さない） |
| SDKの `sessionId` | 会話の継続にのみ使う。接続の同一性には使わない（新規会話の初回は `null` のため） |
| 保持 | `Map<connectionId, Session>`（インメモリ） |
| 同時実行 | 制限なし。`connectionId` が違えば並行して走る |
| 同一 `connectionId` への連投 | 後勝ち（既存を abort）。現状の挙動を維持する |
| 権限承認 | `requestId` をセッションに紐づけ、他セッションからの承認は拒否する |

## フェーズ1: セッションのMap化

**目標**: サーバ内部が `Map<connectionId, Session>` になり、`connectionId` 未指定でも従来どおり1セッションで動作する。

グローバル変数 `currentSession` / `currentStream` / `permissionResolvers` / `questionResolvers` をセッション単位に畳み込む。このフェーズでは API 契約を変えず、ルート側は暫定の既定キー（`"default"`）を渡して従来動作を保つ。単体でアプリが起動・動作することを確認できる単位に収めるのが狙い。

### タスク

- [x] **P1-2**: `currentSession` / `currentStream` を廃し `const sessions = new Map<string, Session>()` に置換（`server/claude/executor.ts`）
- [x] **P1-3**: `permissionResolvers` / `questionResolvers` をセッションのフィールドへ移し、`resolvePermission` / `resolveQuestion` が `connectionId` を受け取って自セッションの `requestId` のみ解決するようにする（`server/claude/executor.ts`）

### 完了確認

```bash

  -H 'X-Connection-Id: 11111111-1111-1111-1111-111111111111' \
  -d '{"message":"1から3まで数えて","repoId":"<repoA>"}' &
curl -N -X POST localhost:3000/api/chat -H 'Content-Type: application/json' \

  -d '{"message":"4から6まで数えて","repoId":"<repoB>"}' &
wait
# 期待: どちらも中断されず最後まで流れ、互いの出力が混ざらない
```

## 注意点

- **`sessionStorage` はタブ複製で引き継がれる**。「タブを複製」した直後の2タブは同じ `connectionId` を持ち、後勝ちで片方が中断される。稀なケースとして許容する
- **SDK子プロセスが同時セッション数だけ起動する**。同時実行は制限なしの方針だが、実メモリを食うのでフェーズ4の上限で歯止めをかける
- **`prefetchModels()` は使い捨ての `query()` を使っており、チャット用セッションには触れない**。Map化の影響を受けないことを確認しておく
- **`server/routes/{files,git,repos,sessions,models}.ts` は対象外**。これらはリクエストごとに完結しており、共有状態を持たない
