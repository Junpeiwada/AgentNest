## 概要

プロンプト入力フィールドの上に、**モデル**と **Thinking effort** を選択できる設定 UI を追加する。
普段は現在の選択値を 1 行で表示し、タップすると設定パネルが上に展開する「トグルバー型」を採用する。

> **システム構成・技術スタック**については [CLAUDE.md](../CLAUDE.md)、画面全体の設計については [設計-画面.md](設計-画面.md) を参照。

- **ステータス**: 実装済み（デフォルト実体名の併記のみ未対応 — [実装タスク](#実装タスク)参照）
- **対象画面**: チャット画面（`/:repo/chat`）の入力エリア

## レイアウト

入力バー（画像ボタン＋テキスト＋送信ボタン）の直上に「トグルバー」を常時表示し、その上に「設定パネル」が展開する。

**モデルは縦リスト**（数が可変・説明併記のため）、**effort は横セグメント**（段階が少なく固定的なため）で表現する。
ラジオボタン（○●）ではなく、選択中の項目をハイライトする UI とする。

```
       ┌────────────────────────────────────────────────┐
       │  モデル / Model                                   │  ← 設定パネル
       │  ┌──────────────────────────────────────────┐   │     (トグルで開閉)
       │  │● おまかせ / Default（前回: Opus 4.8）      │   │  ← 縦リスト
       │  │   CLIの既定モデルに任せる                  │   │     選択中は
       │  ├──────────────────────────────────────────┤   │     行ハイライト
       │  │○ Claude Opus 4.8                         │   │
       │  │   最も高性能。複雑なコーディング向け        │   │
       │  ├──────────────────────────────────────────┤   │
       │  │○ Claude Sonnet 4.6                       │   │
       │  │   バランス型。日常的なコーディング向け      │   │
       │  ├──────────────────────────────────────────┤   │
       │  │○ Claude Haiku 4.5  / Fable 5 …(自動追加) │   │
       │  └──────────────────────────────────────────┘   │
       │ ──────────────────────────────────────────────  │
       │  Thinking effort      ※対応段階のみ表示           │
       │  ┌────┬────┬────┬─────┬─────┐                   │  ← 横セグメント
       │  │ 低 │ 中 │ 高 │最高 │最大 │                   │     選択中を
       │  │low │med │high│xhigh│ max │                   │     塗りつぶし
       │  └────┴────┴────┴─────┴─────┘                   │
       └────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────┐
│ ⚙ Sonnet 4.6 · effort: 中/medium                 ▴   │  ← トグルバー(常時表示)
├──────────────────────────────────────────────────────┤
│  [画像プレビュー行]  (画像添付時のみ)                    │
├──────────────────────────────────────────────────────┤

└──────────────────────────────────────────────────────┘
```

### UI 表現の方針

| 項目 | 表現 | 理由 |
|------|------|------|
| モデル | **縦リスト**（選択行ハイライト・説明併記） | 数が可変（Fable 等で増える）。横並びは iPhone 幅で破綻するため縦が安全 |
| Thinking effort | **横セグメントコントロール**（連結ボタン） | 段階が最大 5 個と少なく固定的。横並びが収まる |

### モバイル（iPhone Safari）対応

本プロジェクトは iPhone Safari での快適操作が要件（[仕様-AgentNest全体.md](仕様-AgentNest全体.md) 参照）。設定パネルは以下を満たす。

- パネルには**最大高さ**を設け、モデルが多い場合はパネル内を**縦スクロール**させる（入力欄やキーボードを覆い隠さない）。
- ソフトキーボード表示時は、`MessageInput` 既存の `visualViewport` 監視（[MessageInput.tsx](../frontend/src/components/MessageInput.tsx)）と整合させ、パネルがキーボードに隠れない位置に出す。
- セグメント各ボタン・モデル行のタップ領域は **44px 程度**を確保する。
- effort セグメントが iPhone 幅に収まらない場合に備え、横スクロール可（折り返さない）とする。

## モデル選択

### 動的取得（ハードコードしない）

モデル一覧は固定で持たず、Claude Agent SDK（`@anthropic-ai/claude-agent-sdk`、現 v0.3.177）から動的に取得する。
`query()` の戻り値が持つ **`supportedModels(): Promise<ModelInfo[]>`** を利用する（後述「[モデル一覧の取得タイミングとキャッシュ](#モデル一覧の取得タイミングとキャッシュ)」参照）。

`ModelInfo` の主なフィールド:

| フィールド | 用途 |
|-----------|------|
| `value` | API 呼び出しに使うモデル ID |
| `displayName` | UI に表示する名称（そのまま表示） |
| `description` | UI に表示する説明（そのまま表示） |
| `supportsEffort` | `false` の場合、Thinking effort 行を非表示 |
| `supportedEffortLevels` | `('low' \| 'medium' \| 'high' \| 'xhigh' \| 'max')[]` 対応する段階のみ表示 |
| `supportsAdaptiveThinking` | 参考情報（将来利用） |
| `supportsFastMode` | 参考情報（将来利用） |

> この方式により、SDK 更新で新モデル（例: Fable）が追加されれば、**コード改修なしに UI へ自動反映**される。

### モデル一覧の取得タイミングとキャッシュ

`supportedModels()` は**トップレベル関数ではなく `query()` の戻り値（`Query` オブジェクト）のメソッド**である。
そのため一覧取得には Claude Code CLI のサブプロセス起動が伴い、**`GET /api/models` のたびに毎回起動するのはコスト過大**。以下の方針とする。

- **サーバ起動時に一度だけ取得し、メモリにキャッシュする**。`GET /api/models` はキャッシュを返すだけにする。
  - 取得経路は `query()` を起動して `supportedModels()` を呼ぶ、または `initializationResult()` の戻り値 `SDKControlInitializeResponse.models`（同じ `ModelInfo[]`）を使う。実装時にどちらか軽い方を選ぶ。
- キャッシュは `executor.ts` 側で保持し、`server/routes/` の `models` ルートから参照する（query() 呼び出しを `executor.ts` に集約する既存方針に合わせる）。
- 一覧取得に失敗した場合は、フロントは**「おまかせ」のみ**を選択肢として表示し、機能は縮退動作させる（モデル/effort なしで送信可能）。

### 「おまかせ / Default」選択肢

- SDK 0.3.177 の `supportedModels()` は**先頭に `value:"default"`（`displayName:"Default (recommended)"`）を含めて返す**。これをそのまま「おまかせ」として扱い、UI 側で固定追加はしない。
- **初期選択はこの `default`**（`DEFAULT_MODEL_VALUE`）とする。
- 「おまかせ」選択時も `POST /api/chat` に `model:"default"` を**明示送信**する（一覧の正規エントリであり SDK が受理する。特別扱いの分岐を持たない）。一覧に存在しない未知値のみサーバ側 `sanitizeModelOptions` で落とし、CLI 既定へ委譲する。
- 「おまかせ」選択時は Thinking effort 行を**非表示**とし、`effort` も送らない。
  - **理由**: SDK では `model` と `effort` は独立したオプションだが、「おまかせ」では既定モデルの実体が事前に分からない（後述の実測まで不明）。そのモデルが effort に対応するか保証できないため、非対応モデルへ effort を渡す事故を避ける目的で effort を送らない。実体が判明しても本仕様では送らない方針を維持する（おまかせ＝SDK の既定挙動に完全委譲）。

#### デフォルトの実体名の併記

Claude Code 本体と同様に「おまかせ」にデフォルトの実体名（例: `おまかせ / Default（前回: Opus 4.8）`）を併記する。
ただし **SDK には「現在のデフォルトモデルが何か」を返す API が存在しない**ため、以下の方針で実測値を取得して表示する。

- SDK が**存在しない理由（確認済み）**: `ModelInfo` に `isDefault` 等のフラグはなく、`SDKControlInitializeResponse`（`initializationResult()`）が返すのは `commands` / `agents` / `models` / `account` / `fast_mode_state` のみで、デフォルトモデルを示す値は含まれない。
- **実測手段**: Claude からの応答メッセージ（`SDKAssistantMessage.message`、Anthropic API の `BetaMessage`）に、実際に使われたモデル ID（`model` フィールド）が含まれる。「おまかせ」で送信した際の応答からこの値を拾い、`supportedModels()` の `displayName` に突き合わせて表示する。
- **メインエージェントのみ採用（誤検出防止）**: サブエージェント（Task ツール等）は別モデルで動くことがあるため、応答の `model` を無条件に採用してはならない。`SDKAssistantMessage.parent_tool_use_id === null`（＝メインエージェントの直接応答）のメッセージの `model` のみを採用する。
- **突合に失敗した場合**: 拾った `model` ID が `supportedModels()` のどの `value` にも一致しない場合（内部エイリアス・一覧外の新モデル等）は、`displayName` の代わりに**生の ID 文字列をそのまま併記**する（表示が消えるよりは ID でも出す）。
- **表示タイミング**: 初回送信までは実体が不明なため `おまかせ / Default` のみ表示。送信後は localStorage に記録し、次回以降は `おまかせ / Default（前回: {displayName}）` と併記する。あくまで「前回値」であり、設定変更後は実際の既定モデルと一致しない場合がある旨を許容する。

## Thinking effort

### 設計方針: effort のみを扱い、thinking の ON/OFF スイッチは設けない

SDK には thinking に関する独立した 2 つのオプションがある。

| オプション | 役割 |
|-----------|------|
| `thinking?: ThinkingConfig` | thinking の**モード**。`{type:'adaptive'}`（Claude が自動判断・新世代モデルの既定）/ `{type:'enabled', budgetTokens}`（固定トークン予算・旧モデル用）/ `{type:'disabled'}`（thinking オフ） |
| `effort?: EffortLevel` | 応答にかける**労力の強さ**。SDK 説明では「adaptive thinking と連動して thinking の深さを導く」とある |

Claude Code 本体には thinking の独立 ON/OFF スイッチがあるが、これは旧来の `thinking: enabled/disabled` 由来。
**本仕様では `thinking` オプションには触れず（SDK 既定の `adaptive` に委譲）、ユーザーには `effort` のみを選ばせる**。

- 理由: 新世代モデル（Opus 4.6+ 等）では thinking は `adaptive` が既定で、Claude が「いつ・どれだけ考えるか」を自動判断する。その深さは `effort` で誘導できるため、ON/OFF スイッチを別途設けなくても実用上十分。UI もシンプルになる。
- 将来 thinking を明示的に OFF にしたいニーズが出た場合は、effort セグメント先頭に「なし」を足して `thinking: { type: 'disabled' }` を送る拡張余地がある（現時点では未採用）。

### effort レベル

- SDK の effort レベルは `EffortLevel = 'low' | 'medium' | 'high' | 'xhigh' | 'max'`（SDK 0.3.177 で `xhigh` が追加された）。
- **選択中のモデルが対応する段階（`supportedEffortLevels`）のみ**をボタンとして表示する。
- `supportsEffort` が `false` のモデル、および「おまかせ」選択時は effort 行を非表示にする。
- ラベルは**日英併記**とする。

| value | 表示ラベル |
|-------|-----------|
| `low` | 低 / low |
| `medium` | 中 / medium |
| `high` | 高 / high |
| `xhigh` | 最高 / xhigh |
| `max` | 最大 / max |

> `xhigh` / `max` は一部の上位モデルのみ対応する（SDK 型定義のコメント参照）。本仕様は `supportedEffortLevels` から動的に段階を絞るため、対応しないモデルでは該当ボタンが出ない。レイアウト図は全 5 段階を例示しているだけで、実際の表示はモデル依存。

## 状態管理・永続化

- フロント state: `selectedModel`（`"default"` または `ModelInfo.value`）、`selectedEffort`（`EffortLevel | null`）。
- 選択値は **localStorage に保存**し、次回起動時に復元する（キー例: `agentnest.model` / `agentnest.effort`）。
- 復元した実モデルが現在の `supportedModels()` に存在しない場合は、**「おまかせ」へフォールバック**する。
- **effort の正規化は「モデル切替時」と「起動時の復元直後」の両方で行う**（同じロジックを通す）。具体的には:
  - 選択モデルが `supportsEffort === false`、または「おまかせ」の場合 → `selectedEffort` を `null` にする。
  - `selectedEffort` が選択モデルの `supportedEffortLevels` に含まれない場合 → 対応する段階の先頭、または `null` に補正する（SDK 更新で対応段階が変わるケースに対応するため、復元時にも必須）。
- 「おまかせ」送信時に応答から得た実体モデル ID を localStorage に保存し、次回の併記表示に使う。
  - **リポジトリ単位で保存する**。`settingSources: ["user","project","local"]`（[executor.ts](../server/claude/executor.ts)）によりリポジトリ別に既定モデルが設定されうるため、単一グローバルキーだと別リポジトリの値で上書きされ併記が嘘になる。キーはリポジトリ単位（例: `agentnest.defaultModelSeen.{repo}`）とする。

## トグルバー（閉時）の表示

| 状態 | 表示 |
|------|------|
| 「おまかせ」選択時（実体未取得） | `⚙ おまかせ / Default` |
| 「おまかせ」選択時（実体取得済み） | `⚙ おまかせ / Default（前回: {displayName}）` |
| 実モデル選択（effort あり） | `⚙ {displayName} · effort: {日本語/英語}` |
| 実モデル選択（effort 非対応） | `⚙ {displayName}` |
