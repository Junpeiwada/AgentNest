## 概要

プロンプト入力フィールドの上に、Claude Code SDK の **permissionMode（実行モード）** を選択できる UI を追加する。
モデル / Thinking effort の選択UI（[仕様-モデル選択.md](仕様-モデル選択.md)）とは**独立した別のボタン**として実装する。

- **ステータス**: 実装済み（SDK の `acceptEdits` / `auto` / `plan` 実挙動の実機確認は残）
- **対象画面**: チャット画面（`/:repo/chat`）の入力エリア

> **システム構成・技術スタック**については [CLAUDE.md](../CLAUDE.md)、画面全体の設計については [設計-画面.md](設計-画面.md) を参照。

---

## 背景: 現状の Auto トグルとの関係

現状の権限制御は、ヘッダーの「Auto」トグル（`autoEdit: boolean`）の1つだけ。

- ON: `Edit` / `Write` / `MultiEdit` をサーバ側 `canUseTool` で自動承認（SDK 的には `acceptEdits` 相当の独自実装）
- OFF: 危険操作を都度 `PermissionDialog` で確認（`default` 相当）
- サーバの `permissionMode` は常に `"default"` 固定で、SDK 本来のモードは使っていない

本仕様では、**ヘッダーの「Auto」トグルを削除**し、入力欄上の「実行モードボタン」に置き換える。
`acceptEdits`（編集自動）を含む4モードを SDK の `permissionMode` として正式に扱う。

---

## 対象モード

SDK の `PermissionMode`（`'default' | 'acceptEdits' | 'auto' | 'plan' | 'bypassPermissions' | 'dontAsk'`）のうち、以下の **4 つ**を載せる。`bypassPermissions` / `dontAsk` は当面除外（事故リスク・`allowDangerouslySkipPermissions` 必須のため）。

英語ラベルは Claude Code 本体の表記に揃える。

| モード値 | 日本語 | 英語（Claude Code 準拠） | アイコン | 意味 |
|---|---|---|---|---|
| `acceptEdits` | 編集自動 | Edit Automatically | ⚡ | ファイル編集(Edit/Write/MultiEdit)を自動承認。**初期選択**（現 Auto ON 相当）。 |
| `default` | 都度確認 | Ask before edits | ⌗ | 危険操作のたびに確認ダイアログ。最も安全（現 Auto OFF 相当）。 |
| `auto` | 自動判断 | Auto mode | ✨ | モデル分類器が承認/拒否を自動判断。 |
| `plan` | プランのみ | Plan mode | ◷ | ツールを実行せず計画だけ立てる。読み取り中心。 |

> 表示順は「編集自動 → 都度確認 → 自動判断 → プランのみ」。アイコンは MUI の Rounded アイコンで近いものを採用（例: `BoltRounded` / `RuleRounded` / `AutoAwesomeRounded` / `ChecklistRtlRounded`）。実装時に確定。
>
> **日英併記**: 表示ラベルは日本語と英語を併記する（モデル選択UIの effort ラベルと同じ流儀）。英語は Claude Code 本体の表記に揃える。`MODE_LABELS: Record<PermissionMode, { ja: string; en: string }>` で持つ。
> - `acceptEdits`: { ja: "編集自動", en: "Edit Automatically" }
> - `default`: { ja: "都度確認", en: "Ask before edits" }
> - `auto`: { ja: "自動判断", en: "Auto mode" }
> - `plan`: { ja: "プランのみ", en: "Plan mode" }

## レイアウト

### 入力欄上の横並び

入力バー（画像ボタン＋テキスト＋送信ボタン）の直上に、以下を**同じ行に横並び**で配置する。

```
┌────────────────┐ ┌──────────────────┐
│⚙ Opus・effort:高│ │⚡ Edit Automatically│   ← 左: モデル/effort トグルバー（既存）
└────────────────┘ └──────────────────┘     右: 実行モードボタン（本仕様）
┌──────────────────────────────┐
│ Message AgentNest...          │   ← 入力バー
└──────────────────────────────┘
```

- 左に既存の「モデル/effort トグルバー」、右に「実行モードボタン」。
- 行内に収まらない狭幅（iPhone）では横スクロール、または左側のトグルバーを `flex: 1` で伸縮させてモードボタンは固定幅とする（実装時に確認）。
- 既存トグルバーの高さ（`minHeight: 36`）・角丸・配色（`background.paper` / `border`）に揃えて統一感を出す。

### モードボタン（閉時）の表示

現在選択中のモードを「アイコン＋英語ラベル」で1行表示（閉時は英語ラベル `MODE_LABELS[mode].en`、Claude Code 準拠）。狭幅ではラベルを隠してアイコンのみにフォールバック可。

```
┌────────────────────┐
│ ⚡ Edit Automatically ▾ │
└────────────────────┘
```

### ポップオーバー（開時）

ボタンを押すと、**ボタン直上にポップオーバー**でモード一覧を表示。選択すると即座に閉じる。

```
  ┌──────────────────────────────────┐
  │✓ ⚡ 編集自動  Edit Automatically   │  ← 選択中はチェック＋アクセント色
  │  ⌗ 都度確認  Ask before edits     │
  │  ✨ 自動判断  Auto mode           │
  │  ◷ プランのみ Plan mode           │
  └────────────▽─────────────────────┘   ← 吹き出しの三角はボタンを指す
┌────────────────────┐
│ ⚡ Edit Automatically ▾ │
└────────────────────┘
```

- 各行: アイコン＋日本語ラベル＋英語ラベルを併記。日本語を主（通常サイズ・濃色）、英語を従（小さめ・淡色）で表示する。
- 選択中の行はチェックアイコン＋アクセント色（`accent.soft` 背景）。
- タップ領域は最低 44px 高さを確保（モバイル）。
- MUI の `Popover`（`anchorEl` = ボタン、`anchorOrigin: { vertical: 'top' }` / `transformOrigin: { vertical: 'bottom' }`）で実装し、外側タップ・Esc で閉じる。
- モデル/effort パネルとは独立し、片方を開いてももう片方は連動しない。

## 状態管理・永続化

- フロント状態名: `permissionMode: PermissionMode`（`'default' | 'acceptEdits' | 'auto' | 'plan'`）。
- localStorage キー: `agentnest.permissionMode`。
- 初期値: 既存ユーザーの体験を変えないため **`acceptEdits`**（現 Auto ON がデフォルトだったため）。保存値が対象4モード外なら `acceptEdits` にフォールバック。
- `useChat` に `permissionMode` / `setPermissionMode` を追加し、`ref` 経由で `sendMessage` から最新値を参照（モデル/effort と同じパターン）。
- **既存 `autoEdit` の扱い**: `MinimalLayout` / `RootLayout` / `Header` から `autoEdit` 関連の state・props・トグルUIを削除。`acceptEdits` がそれを内包する。

## サーバ側の反映

- `POST /api/chat` のリクエストボディに `permissionMode` を追加（現 `autoEdit` を置換）。
- `server/routes/chat.ts`: `permissionMode` を受け取り、未知値は `acceptEdits` にサニタイズして `executeChatFn` へ渡す。
- `server/claude/executor.ts`:
  - `runQuery` の `query({ options })` で、固定だった `permissionMode: "default"` を**受け取った値**に差し替える。
  - `canUseTool` 内の `autoEdit` 分岐（Edit/Write/MultiEdit の自動承認）は、`permissionMode === 'acceptEdits'` を SDK 側が解釈するため、**SDKに委ねて独自分岐を削除**できる。
    - ただし SDK の `acceptEdits` が `canUseTool` を呼ぶ前に自動承認するか、`canUseTool` 内で判断が要るかは SDK 挙動の確認が必要（[実装タスク](#実装タスク)）。挙動次第では `canUseTool` 側の分岐を残し `permissionMode` に同期させる。
  - `AskUserQuestion` の特別扱いは現状維持。

---

## plan モードの扱い

- `permissionMode: 'plan'` を渡すと、SDK は「ツールを実行せず計画を立てる」モードで動作する。
- 計画提示後、ユーザーが実行に移りたい場合のフロー（plan→実行への遷移UI）は**本仕様のスコープ外**。当面は「次のメッセージで別モードに切り替えて送る」運用とする。
- 将来的に「このプランで実行」ボタンを設けるかは別途検討。
